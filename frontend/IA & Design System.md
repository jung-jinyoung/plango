# IA & Design System 정의

## 1. Information Architecture (IA)

### 전체 서비스 구조

```
Plango
│
├── [비로그인 영역]
│   ├── A1. 랜딩 페이지
│   └── A2. 회원가입/로그인
│
├── [최초 진입]
│   └── A3. 온보딩 (첫 목표 설정)
│
└── [로그인 영역 — 핵심 서비스]
    │
    ├── B. 대시보드 (캘린더 허브)
    │   ├── B1. 월간 뷰
    │   ├── B2. 주간 뷰
    │   └── B3. 일간 뷰
    │
    ├── C. 목표 관리
    │   ├── C1. 월간 목표 입력/수정
    │   ├── C2. 주간 목표 입력/수정
    │   └── C3. 목표 계층 트리 뷰
    │
    ├── D. 일간 계획 (AI)
    │   ├── D1. 할 일 더미 입력
    │   ├── D2. AI 추천 결과
    │   ├── D3. 확정/재배치
    │   ├── D4. 완료 체크 & 기록
    │   ├── D5. 미완료 이월 처리
    │   └── D6. 일정 충돌 알림
    │
    ├── E. 회고
    │   ├── E1. 주간 회고 리포트
    │   ├── E2. 월간 회고 리포트
    │   └── E3. 회고 히스토리 아카이브
    │
    ├── F. 통합 기록 화면
    │
    └── G. 설정
        ├── G1. 프로필/설정
        ├── G2. 목표 카테고리 관리
        └── G3. 빈 상태(Empty State)
```

### 구조적 특징

Plango의 IA는 전통적인 "메뉴 트리형"이 아니라, **캘린더(B)를 중심 허브로 두고 목표(C)·계획(D)·회고(E)가 모두 캘린더에서 파생·회귀하는 방사형 구조**입니다. 이는 User Flow에서 정의한 순환 구조(월간→주간→일간→회고→월간)를 IA에도 그대로 반영한 것입니다.

---

### 화면 간 이동 관계

| 출발 화면            | 이동 방식               | 도착 화면                   |
| -------------------- | ----------------------- | --------------------------- |
| A1 랜딩              | CTA 클릭                | A2 회원가입/로그인          |
| A2 로그인            | 최초 로그인 시          | A3 온보딩                   |
| A2 로그인            | 재방문 시               | B1 월간 뷰 (기본 진입점)    |
| A3 온보딩            | 첫 목표 입력 완료       | B1 월간 뷰                  |
| B1 월간 뷰           | 탭 전환                 | B2 주간 뷰                  |
| B2 주간 뷰           | 탭 전환                 | B3 일간 뷰                  |
| B1/B2                | 목표 카드 클릭          | C1/C2 목표 입력/수정 (모달) |
| B1/B2/B3             | 목표 클릭 (역방향 추적) | C3 목표 계층 트리 뷰        |
| B3 일간 뷰           | "할 일 추가" 클릭       | D1 할 일 더미 입력          |
| D1                   | AI 추천 요청            | D2 AI 추천 결과             |
| D2                   | 추천 확정               | D3 확정/재배치 (B3에 반영)  |
| D3 → 실행 중         | 체크/메모               | D4 완료 체크 & 기록         |
| D4 (하루 종료 시)    | 미완료 존재             | D5 미완료 이월 처리         |
| B3 실행 중           | 새 일정 충돌 발생       | D6 충돌 알림 (모달)         |
| B2 (주 종료 시점)    | 자동/수동 트리거        | E1 주간 회고 리포트         |
| E1                   | "다음 주 목표로"        | C2 주간 목표 입력 (복귀)    |
| B1 (월 종료 시점)    | 자동/수동 트리거        | E2 월간 회고 리포트         |
| E2                   | "다음 달 목표로"        | C1 월간 목표 입력 (복귀)    |
| E1/E2                | "지난 회고 보기"        | E3 회고 히스토리 아카이브   |
| 모든 화면            | 사이드바 아이콘         | F 통합 기록 화면            |
| 모든 화면            | 헤더 프로필 아이콘      | G1 설정                     |
| B/D/E 데이터 없음 시 | 자동                    | G3 빈 상태                  |

**핵심 이동 원칙:** 회고(E)는 항상 상위 목표 설정(C)으로 되돌아가는 진입점을 가져야 하며, 이것이 Plango Loop를 실제 내비게이션 구조로 구현하는 지점입니다.

### Navigation 구조

**Primary Navigation (Sidebar, 좌측 고정)**

```
[로고]
─────────
◆ 대시보드 (월/주/일 전환은 대시보드 내부 탭)
◆ 목표 관리
◆ 회고
◆ 통합 기록
─────────
◆ 설정
[프로필]
```

**Secondary Navigation (대시보드 내부, 상단 탭)**

```
[월간] [주간] [일간]
```

- Primary Navigation은 "무엇을 볼지"(목표/회고/기록)를 결정
- Secondary Navigation은 "어느 시간 단위로 볼지"(월/주/일)를 결정
- 이 둘의 조합으로 예를 들어 "목표 관리 > 주간" 같은 조합적 접근이 가능해야 함

### Sidebar 구조

```
┌─────────────────────┐
│ [Plango 로고]        │
├─────────────────────┤
│ 🏠 대시보드           │
│ 🎯 목표 관리          │
│ 📊 회고               │
│ 📝 통합 기록          │
├─────────────────────┤
│ (여백)                │
├─────────────────────┤
│ ⚙️ 설정               │
│ [프로필 아바타] 이름   │
└─────────────────────┘
```

- 고정 폭, 접기/펼치기(collapse) 기능은 넓은 화면 전제이므로 기본은 항상 펼침 상태 유지
- 현재 위치는 아이콘+텍스트에 액센트 컬러로 표시

### Breadcrumb 필요 여부

**결론: 대부분 화면에는 불필요, 목표 계층 트리 뷰(C3)에서만 필요**

- 대시보드, 회고, 통합 기록 등은 깊이가 1~2단계로 얕고, Sidebar + 상단 탭만으로 위치 파악이 충분합니다.
- 단, **C3 목표 계층 트리 뷰**는 "월간 목표 > 주간 목표 > 일간 태스크"로 3단계 깊이를 가지므로, 이 화면 안에서만 breadcrumb 형태의 경로 표시가 필요합니다.
  예: `2024년 5월 목표 > 브랜드 캠페인 런칭 > 콘텐츠 3종 제작`

## 2. 공통 디자인 시스템

### Header

- **목적**: 현재 위치·날짜 컨텍스트 제공, 전역 액션(알림, 프로필) 접근
- **사용 화면**: 전체 로그인 영역 공통
- **구성 요소**: 좌측 현재 뷰 타이틀(예: "2024년 5월"), 중앙 날짜 네비게이션(◀ ▶ 오늘), 우측 알림 아이콘 + 프로필 아바타

### Sidebar

- **목적**: 전역 메뉴 이동(Primary Navigation)
- **사용 화면**: 전체 로그인 영역 공통
- **구성 요소**: 로고, 메뉴 아이템(아이콘+라벨), 활성 상태 인디케이터, 하단 설정/프로필

### Navigation (Tab형, 월/주/일 전환)

- **목적**: 시간 단위 뷰 전환
- **사용 화면**: B1/B2/B3, C1/C2
- **구성 요소**: 3개 탭(월간/주간/일간), 활성 탭 하이라이트, 전환 시 상태 유지(선택한 날짜 컨텍스트 보존)

### Calendar

- **목적**: 일정을 날짜 그리드 위에 시각화
- **사용 화면**: B1(월간), B2(주간), C3(목표-일정 연계 표시)
- **구성 요소**: 날짜 셀, 일정 도트/바 인디케이터, 오늘 날짜 강조, 목표 진행률 미니 표시(월간 뷰)

### Goal Card

- **목적**: 월간/주간 목표를 카드 단위로 표시
- **사용 화면**: B1/B2 사이드 패널, C1/C2, C3
- **구성 요소**: 목표 제목, 진행률 바(Progress Bar), 카테고리 색상 태그, 연결된 하위 목표/태스크 수 배지

### Schedule Card

- **목적**: 개별 일정(시간이 배정된 항목)을 표시
- **사용 화면**: B2, B3, D3
- **구성 요소**: 시간 라벨, 제목, 소요시간 바(타임라인 위 길이로 표현), 카테고리 색상, 드래그 핸들

### Todo Item

- **목적**: 순서 없이 입력된 할 일 항목(시간 미배정 상태)
- **사용 화면**: D1, D5, F
- **구성 요소**: 체크박스, 텍스트, 예상 소요시간(선택 입력), 삭제 아이콘, 드래그 핸들

### Progress Bar

- **목적**: 목표 달성률·완료율 시각화
- **사용 화면**: B1 사이드 패널, C1/C2, E1/E2
- **구성 요소**: 트랙, 채워진 바(퍼센트), 수치 라벨

### AI Recommendation Card

- **목적**: AI가 제안한 우선순위·시간 배치 결과를 표시하고 수용/수정 유도
- **사용 화면**: D2, D3
- **구성 요소**: 추천 배지("AI 추천"), 제안된 시간 블록, 근거 텍스트(예: "마감일 임박"), 수락/수정 버튼

### Modal

- **목적**: 화면 전환 없이 입력/확인 처리 (목표 입력, 일정 충돌 알림 등)
- **사용 화면**: C1/C2 입력, D6 충돌 알림, G2 카테고리 관리
- **구성 요소**: 오버레이, 타이틀, 본문(폼 또는 메시지), 하단 액션 버튼(취소/확인)

### Dialog (확인형, Modal보다 경량)

- **목적**: 단순 확인/경고 (삭제 확인, 이월 여부 확인 등)
- **사용 화면**: D5 미완료 이월, 삭제 액션 전반
- **구성 요소**: 짧은 메시지, 2개 버튼(예/아니오)

### Toast

- **목적**: 비침해적 상태 알림 (저장됨, 오류 등)
- **사용 화면**: 전체 공통
- **구성 요소**: 아이콘, 짧은 메시지, 자동 소멸(3초 내외)

### Empty State

- **목적**: 데이터가 없을 때 다음 행동 유도
- **사용 화면**: G3, B1(목표 없을 때), E3(회고 기록 없을 때)
- **구성 요소**: 일러스트/아이콘, 안내 문구, CTA 버튼(예: "첫 목표 세우기")

### Button

- **목적**: 전역 액션 트리거
- **사용 화면**: 전체 공통
- **구성 요소**: Primary(핑크 #DF5785 배경), Secondary(아웃라인), Text 버튼, 아이콘+텍스트 조합

### Input

- **목적**: 텍스트 입력 (목표, 할 일, 메모 등)
- **사용 화면**: C1/C2, D1, F
- **구성 요소**: 라벨(선택), 텍스트 필드, placeholder, 포커스 상태, 에러 상태

### Dropdown

- **목적**: 카테고리 선택, 정렬 기준 선택 등
- **사용 화면**: C1/C2(카테고리 선택), E1/E2(기간 선택)
- **구성 요소**: 트리거 버튼, 옵션 리스트, 선택 상태 체크 표시

### Tabs

- **목적**: 같은 화면 내 하위 뷰 전환 (Navigation 컴포넌트와 동일 패턴, 로컬 스코프에도 재사용)
- **사용 화면**: B1/B2/B3 전환, E1/E2 전환
- **구성 요소**: 탭 리스트, 활성 인디케이터(밑줄 또는 배경)

### Accordion

- **목적**: 목표 계층 구조를 펼침/접힘으로 탐색
- **사용 화면**: C3 목표 계층 트리 뷰
- **구성 요소**: 헤더(제목+화살표 아이콘), 펼침 콘텐츠(하위 목표/태스크 리스트), 애니메이션 전환

## 3. 화면별 상세 설계

---

### A1. 랜딩 페이지

**화면 목적**: 서비스 소개 및 가입 유도
**주요 사용자 행동**: 스크롤로 서비스 이해, CTA 클릭
**포함 UI 컴포넌트**: Header(로고+CTA 버튼), Button
**화면 레이아웃**

```
Header (로고 / 로그인·가입 버튼)
Hero (슬로건, 목업 이미지, CTA)
Key Feature 요약 섹션
Footer
```

**화면 이동**: → A2 회원가입/로그인

---

### A2. 회원가입/로그인

**화면 목적**: 계정 생성 또는 인증
**주요 사용자 행동**: 이메일/소셜 로그인 입력
**포함 UI 컴포넌트**: Input, Button
**화면 레이아웃**

```
중앙 정렬 카드
├─ 로고
├─ Input (이메일)
├─ Input (비밀번호)
├─ Button (로그인/가입)
└─ 소셜 로그인 버튼
```

**화면 이동**: 최초 가입 → A3 온보딩 / 기존 사용자 → B1 월간 뷰

---

### A3. 온보딩 (첫 목표 설정)

**화면 목적**: 첫 사용 진입 시 월간 목표를 입력하도록 유도
**주요 사용자 행동**: 이번 달 목표 1개 이상 입력
**포함 UI 컴포넌트**: Input, Button, Progress Bar(온보딩 진행 단계)
**화면 레이아웃**

```
Header (온보딩 진행 단계 표시)
안내 문구 ("이번 달 목표를 세워볼까요?")
Input (목표 입력, 다건 추가 가능)
Button ("시작하기")
```

**화면 이동**: 완료 → B1 월간 뷰

---

### B1. 월간 뷰 (대시보드 - 월간)

**화면 목적**: 이번 달 전체 일정과 목표를 한눈에 확인
**주요 사용자 행동**: 날짜 이동, 목표 확인, 목표 카드 클릭, 뷰 전환
**포함 UI 컴포넌트**: Header, Sidebar, Navigation(탭), Calendar, Goal Card, Progress Bar
**화면 레이아웃**

```
Header
Sidebar | Navigation(월/주/일)
        | Goal Panel (월간 목표 리스트, Goal Card + Progress Bar)
        | Calendar (월간 그리드)
```

**화면 이동**: 목표 카드 클릭 → C1 (모달) / 특정 날짜 클릭 → B3 일간 뷰 / 탭 전환 → B2

---

### B2. 주간 뷰

**화면 목적**: 이번 주 일정과 주간 목표 확인
**주요 사용자 행동**: 요일별 일정 확인, 주간 목표 확인, 일정 드래그 조정
**포함 UI 컴포넌트**: Header, Sidebar, Navigation, Calendar(주간 그리드), Goal Card, Schedule Card
**화면 레이아웃**

```
Header
Sidebar | Navigation(월/주/일)
        | Goal Panel (주간 목표)
        | Calendar (7일 그리드, Schedule Card 배치)
```

## 5. UX 원칙

1. **목표는 항상 보인다.** 어떤 화면(월간/주간/일간/기록)에 있든, 현재와 연결된 목표(월간·주간)가 사이드 패널 또는 헤더에 상시 노출된다.
2. **월·주·일은 언제든 전환 가능하다.** Navigation 탭은 모든 대시보드 화면에서 동일한 위치에 고정되며, 전환 시 스크롤/선택 상태가 유지된다.
3. **드래그 앤 드롭은 모든 일정에서 지원된다.** Schedule Card, Todo Item 모두 드래그로 재배치 가능해야 하며, 마우스 오버 시 드래그 핸들이 시각적으로 드러난다.
4. **AI 추천 결과는 항상 수정 가능하다.** AI Recommendation Card는 "수락"만이 아니라 개별 항목 단위의 수정·거부가 가능해야 하며, AI 제안이 최종 결정을 대체하지 않는다.
5. **계획→실행→회고 흐름이 항상 유지된다.** 회고 화면(E1/E2)에는 반드시 다음 목표 설정(C2/C1)으로 이어지는 CTA가 있어야 하며, 흐름이 끊기는 막다른 화면(dead-end)이 없어야 한다.
6. **넓은 화면을 전제로 정보 밀도를 높인다.** 모바일 앱처럼 정보를 숨기거나 여러 단계로 분산시키지 않고, 가능한 많은 컨텍스트(목표+일정+진행률)를 한 화면에 동시에 노출한다.
7. **입력은 형식을 강제하지 않는다.** 할 일 입력(D1)은 순서·우선순위·카테고리를 요구하지 않으며, 이런 구조화는 AI가 사후에 수행한다.
8. **모든 변경은 즉시 반영되고 되돌릴 수 있다.** 드래그 재배치, 완료 체크 등은 별도 저장 버튼 없이 즉시 반영되며, 실행취소(undo)가 가능해야 한다.
9. **회고는 수동적 열람이 아니라 다음 행동의 출발점이다.** 회고 화면은 항상 "그래서 다음엔 어떻게 할지"로 연결되는 CTA를 포함한다.
10. **키보드 우선 입력을 지원한다.** 목표/할 일 입력 시 마우스 없이 키보드만으로 연속 입력(Enter로 다음 항목 추가 등)이 가능해야 한다.
